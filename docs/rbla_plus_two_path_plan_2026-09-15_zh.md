# RBLA / 新版 RBLA+：两条训练路径上的广播交叉消融

日期：2026-09-15。已按用户最新澄清修订：**左侧是完整训练路径，右侧只表示广播方法；四个值是广播后客户端模型的准确率。**

RBLA+ 唯一指带双向 RankScale 的当前版本。旧的不带 RankScale 的 RBLA+/SP+ 不作为独立训练方法。

**实现更新（2026-09-15）：** 用户要求按 KISS 原则改用 `aggregation_broadcast_error` 的原生训练和 CSV 记录流程。现行入口为 `src/test/rbla+/ablation/spectum_ablation/`；以该目录 `README.md` 为准。以下保存旧方案背景；其中显式配对缓存、自定义断点恢复、离线分析框架不再是现行实现功能。六个正式训练任务尚未启动。

## 1. 两条路径、四组准确率

| 完整训练路径 | 用 RBLA 广播 | 用 RBLA+ 广播 |
|---|---|---|
| RBLA | **RBLA/RBLA** | **RBLA/RBLA+** |
| RBLA+ | **RBLA+/RBLA** | **RBLA+/RBLA+** |

同一行、同一轮的两个广播方法，共用这条路径已经完成的**同一份聚合因子**。只更换广播处理，不重新聚合，不重做或撤销上传 RankScale。

两条完整训练路径独立推进：

- RBLA 路径始终由 RBLA 聚合和 RBLA 广播产生下一轮真实客户端状态。
- RBLA+ 路径始终由新版 RBLA+ 的上传对齐、聚合、谱处理与下发对齐产生下一轮真实客户端状态。
- 非对角广播只在独立副本上构造模型、计算准确率，结果不写回训练。

四组结果不是四条完整训练轨迹，也不是四次随机重复。两条路径会形成不同的训练状态，因此“相同聚合因子”仅指同一行的两列，不要求两行相同。

## 2. 必须在当前轮谱处理之前保留聚合因子

RBLA+ 的 compact 谱处理发生在 aggregator 的 `_after_aggregation()`。应在 `_do_aggregation()` 已产生 `_aggregated_weight`、而 `_after_aggregation()` 尚未谱重排时保存快照。

两条路径的快照含义分别为：

- RBLA：原始客户端因子直接进行 RBLA 聚合所得的 A/B。
- RBLA+：客户端上传已经做过 RankScale，再进行 RBLA 聚合所得、尚未进行本轮 compact 重分发的 A/B。

**不能从 RBLA+ 已经谱排序后的服务器因子开始，再用原始前缀冒充 RBLA 广播。** 那会让 RBLA 分支提前获得本轮谱排序的好处，削弱或消除要观察的差异。

也不能为交叉广播重新上传或重新聚合。上传 RankScale 属于左侧真实训练路径，右侧仅使用已生成的聚合因子。

快照除 A/B 外，还需要该轮聚合后的非 LoRA 参数和 buffers、客户端实际逐层 rank/shape/scaling、服务器 scaling、路径标签、轮次与哈希。只保存 LoRA 因子不足以恢复完整模型准确率。

## 3. 同一快照上的两个广播算子

设该行聚合因子为 A_g、B_g，服务器实际 scaling 为 s_s，目标客户端实际 scaling 为 s_i。卷积裁切宽度按内部 q 处理，而不是直接拿逻辑 r 当矩阵宽度。

**RBLA 广播：**

1. 保留原始因子槽位顺序。
2. 按客户端真实形状截取前缀，并遵循当前补零/适配逻辑。
3. 不增加原始 RBLA 没有的下发 scale 修正。
4. 客户端模型按实际 s_i 使用收到的 A/B。

**RBLA+ 广播：**

1. 对同一 A_g、B_g 执行现有 compact QR/core-SVD。
2. 使用 `ordering: singular_value`、`overcomplete_policy: zero_pad`。
3. 按当前下发实现，对两个因子各乘 `sqrt(s_s/s_i)`。
4. 经相同客户端形状适配逻辑取谱前缀，构造客户端模型。

当前代码是先对全宽下发因子做每层标量 scale 转换，再截前缀；重放和计时保留该顺序。前缀裁切与每层标量乘法在代数上可交换。

此处没有再次执行上传转换。右侧“RBLA+”准确地指新版 RBLA+ 的广播部分，不表示在这一列重新执行完整服务器步骤。

## 4. 准确率怎样计算，才能看到广播收益

每次广播产生的是不同 rank 的客户端模型，应评估这些模型，而不是只评估全宽服务器模型。

默认每轮对两种广播分别执行：

1. 使用该行同一份聚合后的基础权重、分类头和其他非 LoRA 状态。
2. 按 10 个客户端各自真实逐层 rank/scaling 构造广播后模型，不额外进行本地训练。
3. 在同一完整 held-out 集上评估，统一 preprocessing、batch size、eval mode 和数值精度。
4. 保存每个客户端准确率，以其等权平均作为该组合的主准确率：

```text
broadcast_accuracy(driver, broadcaster, t)
    = (1 / 10) * sum_i accuracy(client_model_i_after_broadcast)
```

因此每个数据集每轮得到四个均值和对应的客户端明细。客户端具有相同完整 rank profile、相同所有模型张量及相同评估设置时，可以复用推理结果，但计算平均时仍按原客户端个数计数。不能只凭一个 rank 数字相同就复用。

所有客户端模型都在同一 held-out 集评估；此处不是各客户端本地测试集上的个性化准确率。MNLI/QQP 应准确注明 GLUE validation，CIFAR-10 使用既有测试 split。

真实训练路径原有的服务器 accuracy/loss 曲线仍正常保存，但另列为 `server_accuracy`。不能把两个服务器准确率直接复制成四个广播准确率。

默认每次实际更新都观察四组合，保留完整曲线。额外推理会增加总耗时，但不会增加完整训练路径数；单张 GPU 顺序执行，复用完全相同状态的评估，计时中单列观察开销。若执行前决定降低观测频率，必须两路径、两广播统一预先固定，最终轮必测，不按观察结果挑轮次。

## 5. 四组结果各回答什么

对同一轮：

- `RBLA/RBLA+ - RBLA/RBLA`：原始 RBLA 训练路径产生的聚合因子上，换用新版广播方法的即时准确率变化。
- `RBLA+/RBLA+ - RBLA+/RBLA`：RBLA+ 训练路径产生的聚合因子上，谱广播是否仍有收益。
- 同一广播方法下比较两条训练路径：观察不同训练历史形成的聚合因子，在相同广播规则下的表现。
- 两个对角组合及其真实训练曲线：对应两种完整算法实际运行后的表现。

非对角结果只是同一轮更换广播方法的即时评估，不表示以该交叉组合继续训练 101 次更新后的结果。四条曲线不能当作四个独立 seed。

## 6. 怎样解释 SP+ 的收益

**CIFAR-10 是最清楚的 SP+ 广播对照。** 当前实例化层的服务器/客户端 scaling 均为 1，两种广播的 scale 因子都为 1。因此同一行两列主要区别是原始前缀与 compact 谱前缀，可以用于解释谱重分发带来的准确率变化。

CIFAR-10 的两条完整训练曲线不要求重合。虽然 scaling 相同，两种广播的低 rank 更新可以不同，继而改变下一轮训练；同一快照的全宽服务器有效更新相同，也不代表客户端广播后模型相同。

MNLI/QQP 的 s_i 通常不等于 s_s。按照两种方法当前真实广播语义，列间差异同时包含**谱前缀与下发 scale 对齐**。这两项结果应称为“新版 RBLA+ 广播的整体收益”，不能完全归因于单独 SP+。

当前方案不因此增加第三条训练路径或恢复旧普通 RBLA+ 版本。纯谱重分发的清晰证据由 scaling=1 的 CIFAR-10 及同目标 checkpoint 重构诊断提供。若将来需要语言任务上严格剥离两部分，再另行定义只改变一个因素的离线广播控制，不混进当前四格。

| 客户端数 / 每轮参与 | 10 / 10 | 10 / 10 | 10 / 10 |

实际客户端逻辑 rank 沿用已核查配置：

```text
CIFAR-10 conv: [16,56,30,42,64,21,49,18,30,44]
CIFAR-10 FC:   [4,14,8,11,16,5,12,4,8,11]
```

CNN 序列已由工厂实例化读取；TinyBERT 序列由当前工厂公式和配置推导，正式开跑仍需核验实例化层。

沿用 `training_rounds=100` 的当前 runner，即日志 round 0…100，**101 次实际更新**。同时保存 `update_index=logged_round+1`。不跑多 seed、mismatch、FLoRIST 或 MRPC。

总预算为 **3 数据集 × 2 完整路径 = 6 次训练**；每个数据集输出四条广播准确率曲线。全程观测时，组合均值表包含 `3×101×4=1212` 条轮次记录；客户端明细另存。

三数据集的六个源配置已写入 `docs/rbla_plus_two_path_protocol_2026-09-15.json`，均为 planned。实际实现映射：

|---|---|---|

## 8. 配对、隔离与对角校验

同一数据集两条训练路径复用相同样本 ID 划分、基础模型、转换前 adapter 初始化、逐层 rank 配置、客户端顺序和本地训练随机流，保存可核验对象与哈希。seed=42 相同不能替代这些配对证据。

初始化各自采用原算法下发语义；有效更新可以相同，但 RankScale 可能缩放初始非零的一侧因子。不能强制转换后因子逐元素相同，也不对初始零有效更新做导致两因子同时为零的谱平衡。

观测需要独立模型和评估对象，`eval()` 与无梯度推理不能改变真实客户端 buffers、训练 RNG、DataLoader 随机状态或后续 dropout 流。构造评估模型本身也可能消耗随机数，必须隔离或保存/恢复。禁止观察分支写回训练。

验收顺序：

1. 同一行两个广播分支的聚合输入哈希完全相同。
2. RBLA 路径的 RBLA 广播分支重现实际广播输出。
3. RBLA+ 路径的 RBLA+ 广播分支重现实际广播输出。
4. 检查实际 scaling 的有效更新一致性，比较 sBA 与预测，记录 dtype/容差；重奇异值情况下不强求不同数值分解返回逐元素相同因子。
5. 短程检查开启观察和关闭观察时，真实训练状态与随机流程一致。
6. 通过后再执行六个完整任务。

## 9. 真实 checkpoint 重构作为辅助证据

两条路径在实际更新 1、10、50、101 保存聚合后、当前轮谱处理前的因子与必要模型状态。原始 RBLA 路径必须保留，不能只用 RBLA+ 训练产生的因子说明原始前缀的问题。

对同一份聚合目标和同一个内部宽度 q，离线比较原始前缀、compact 谱前缀、dense 经济型完整 SVD 后截断的 Frobenius 重构误差、相对 dense 最优参考的额外误差及满宽度误差。

这是固定目标的数值诊断，不是第三条训练路径。真实广播后的有效更新误差还需纳入 s_i/s_s；如果要单独检查截断质量，应使用一致 scaling 的目标矩阵并单独标注。不要把 scale 修正与 rank 截断误差混成一个“SP+ 重构误差”。零范数参照单独处理，卷积明确逻辑 r 与内部 q。

准确率是本次四组合的主要输出；矩阵误差是解释证据，不能替代真实模型评估。

## 10. 运行开销与四格的对应关系

四格右侧现在仅是广播方法，因此四格耗时/峰值内存也只测**广播阶段**：从同一份已驻留服务器的聚合因子开始，到所有请求 rank 的下发权重构造结束。

RBLA+ 广播计入本轮 compact 谱处理、下发 scale 转换和输出构造；RBLA 计入原始前缀及输出构造。复制边界统一，准确率评估、快照落盘和误差/dense 参考计算均在计时之外。

两个完整服务器步骤（包含各自上传处理和聚合）的开销，随两条真实训练路径另报。不能为了填非对角四格而重新聚合，那会改变这次广播消融的定义。

当前 CPU 聚合路径作为主报告；独立重放已保存因子，正确预热、重复计时、报告中位数/IQR。阶段峰值增量内存与 RSS 起止差分开；GPU 测量同步并区分 allocated/reserved。观察所增加的推理成本单独记账，不能算成某个广播算法的开销。

## 11. 实现边界与交付

现有 `fedss_experiment/aggregation_broadcast_error` 提供 driver/evaluated 组织方式，但它在原始上传上重跑各个完整算子，且旧误差使用不含 scaling 的 BA。此次只复用其“真实路径加只读观察”的结构，快照位置移到聚合后、谱处理前；不直接沿用它的算子输入和旧 SP 标签。

独立广播消融入口及观察器已调用当前原始前缀、compact 和 RankScale 下发函数，保存对角校验与输入哈希，并实现配对对象保存和恢复。当前客户端 optimizer 每轮重建，恢复不引入原流程没有的跨轮动量；实际持久模型/RNG/数据顺序状态按轮次提交保存。

输出至少包含：

- 两条真实训练路径的普通服务器准确率与损失日志；
- 四组合逐轮平均广播准确率、每客户端准确率与完整 rank/scaling 元数据；
- 同一路径下两种广播的准确率差值曲线，主表采用末轮；
- 固定 checkpoint 重构误差与广播阶段耗时/内存；
- 配置、代码版本/工作树快照、数据/初始化/聚合输入哈希、状态与恢复文件；
- 原始 CSV/JSON 和可重复生成矢量 PDF 的脚本。

结果缺失记 TBD，不把现有最高服务器准确率填入新的四格广播准确率表。单次试验不报告跨 seed 显著性，也不把不同客户端或不同轮次当作独立训练重复。
